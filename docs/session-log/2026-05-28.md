**Decisions made:**

- **Render, not Cloudflare Pages.** The May 14 LC Kit plan put LM on Cloudflare Pages + Workers. Attempted it; the path failed at the Functions bundling step because the `nodemailer` import chain pulls in 53 Node-only modules and the Workers Node-compat layer plus our `compatibility_date = "2026-05-01"` couldn't reliably polyfill all of them. Compounding issue: Cloudflare Pages' setup wizard pins "Retry deployment" to the original commit SHA, which masked our subsequent fixes. Render runs Express natively, so the entire problem disappears. *Render is now the correct host for LM* — explicit deviation from the May 14 plan, captured in `FORWARD_PLAN.md`. The May 14 plan should be amended for the next time we revisit it.
- **Neon over keeping Manus's TiDB.** Already executed; flagged here for completeness. Postgres-on-Neon over HTTP works from both Render and (if we ever revisit) Workers.
- **Email is stubbed, not removed.** `email.ts` types stay so `routers.ts` continues to typecheck; only `sendEstimateEmail()` throws. This is a deliberate halfway state pending a Resend swap.
- **Branch named `migration/cloudflare` is misleading.** Keeping the name through tonight; renaming when we merge to `main`.
- **Production branch on Render is `migration/cloudflare`, not `main`.** Will flip at merge.
- **DNS for literalmemories.com is unchanged.** Public domain still points at Manus. The Render `*.onrender.com` URL is the only live LM endpoint until cutover.
- **Node_01 framework formalized.** The 3-lane kit (Cloudflare for sync web, Render for async pipelines, Node_01 for heavy-deps local) is now reference-documented in `MANUS_Document_Repository/_docs/specs/node_01_overview.md` with explicit decision criteria. Treat Node_01 as a first-class hosting consideration for every new project, not an afterthought.
